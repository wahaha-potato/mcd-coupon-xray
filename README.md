# 麦门券力透视 · mcd-coupon-xray

> 麦麦省的券谁都能领，但**领了不等于你楼下那家店认**。
>
> 这个 Skill 一键领全，然后逐家门店校验：哪家店真的能核销、券后实付多少、同一张券在哪家店才用得掉。

## 它解决的问题

麦当劳 MCP 里有两个都叫「我的券」的接口，语义完全不同：

| 接口 | 你看到的 | 它校验了什么 |
|---|---|---|
| `query-my-coupons` | 你**拥有**的券 | **什么都没校验** |
| `query-store-coupons` | 某家店 + 某渠道下**能核销**的券 | 门店、渠道、下单规则 |

官方文档自己写得很清楚：

> 该接口返回的是用户拥有的券，**不进行门店、渠道、配送方式等下单规则校验，因此不承诺可用于当前订单**。若业务目标是"当前门店/当前订单可用的券"，请调用 `query-store-coupons`。

于是产生了一个几乎所有人都撞过的体验：卡包里躺着七八张券，兴冲冲走到楼下门店，点开一单，发现一张都用不上。

**「能领」和「能用」之间的差额，就是这个 Skill 要查的东西。**

## 实测到的三个反直觉事实

这三个都是在真实 Token 下跑出来的，不是文档抄的：

**1. 卡包是空的，按门店查也一定是空的**

`query-store-coupons` 不是「返回该店全部可用券」，而是「在**你已持有**的券里筛出该店能用的」。实测：空卡包 + 有效门店 `1951066` → 返回 `[]`。

所以顺序必须是**先领券，再查门店**。反过来做，任何门店都是空的，会得出「这家店一张券都不支持」的错误结论。

**2. 可领券列表的条目数 ≠ 券的数量**

一次调用 `available-coupons` 返回 **5 条**，去重后只有 **3 张券**：

- 19.9 元王牌炸鸡任选 2
- 11.9 元麦辣鸡腿堡
- 免费脆薯饼

重复的两条图片域名不同——一组在 `img.mcd.cn`，另一组是带签名的腾讯云 COS 链接。按条数统计会给用户一个虚高的数字。

**3. 门店经纬度是废的**

`query-nearby-stores` 每家店都返回 `longitude: 0.0`、`latitude: 0.0`，唯一有效的是 `distance`（米）。任何想拿坐标画地图或自己算距离的写法都会失败。

## 怎么用

在 WorkBuddy（或任何支持 MCP 的客户端）里配好麦当劳 MCP，然后直接说：

```
帮我看看我的券哪家店能用
```

```
我想在国贸附近吃，用券之后哪家最便宜
```

Skill 会走完整条链：

```
available-coupons      麦麦省可领券（按券名去重，报出真实张数）
      ↓
auto-bind-coupons      一键领取（写入卡包，纯新增）
      ↓
query-my-coupons       复核卡包，确认券真的进来了
      ↓
query-nearby-stores    拿到 storeCode（收藏为空自动降级为城市+地标搜索）
      ↓
query-store-coupons    逐店校验：这张券这家店认不认
      ↓
query-meals           有可用券的店，取菜单
      ↓
calculate-price       券前 / 券后 / 省多少
```

输出两张表：

| 门店 | 距离 | 可用券 | 最优券 | 券前 | 券后 | 省 |
|---|---:|---:|---|---:|---:|---:|
| 麦当劳北京长虹桥餐厅 | 628m | 2 | 11.9 元麦辣鸡腿堡 | 25.5 | 11.9 | 13.6 |
| 麦当劳北京团结湖餐厅 | 933m | 1 | 免费脆薯饼 | 13.0 | 8.0 | 5.0 |
| 麦当劳北京工体北路餐厅 | 1355m | 0 | — | — | — | — |

外加一张跨店可用性矩阵，直接回答「同一张券哪家店认」。

最后给一句能直接执行的话：**去长虹桥店用 11.9 元麦辣鸡腿堡券，省 13.6 元。**

## 目标用户

- 卡包里攒了一堆券、但从没搞清楚过能不能用的人
- 在几个门店之间犹豫、想选最省钱那家的人
- 公司楼下 / 家楼下有多家麦当劳、想知道哪家券覆盖更好的通勤族
- 用企业团餐 / 得来速、渠道规则更绕的场景

## 安装

**1. 申请 MCP Token**

打开 [open.mcd.cn/mcp](https://open.mcd.cn/mcp)，手机号登录 → 右上「控制台」→「激活」→ 同意协议 → 复制 Token。

**2. 配置 MCP 连接**

本仓库的 `mcp-config.example.json` 是脱敏模板，把 `YOUR_MCP_TOKEN` 换成你的真实 Token：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

WorkBuddy 用户：左侧「专家·技能·连接器」→「连接器」→ 右上「自定义连接器」→「配置 MCP」→ 粘贴上面的 JSON → 保存 → 启用。

**3. 放入 Skill 目录**

把 `SKILL.md` 放到 `~/.workbuddy/skills/mcd-coupon-xray/` 下，重启会话即可。

**4. 自检脚本**

```bash
python scripts/xray.py --selftest
python -m pytest tests/ -v      # 或 python tests/test_xray.py
```

## 边界

- 本项目的结论只对**调用当时**的券状态、门店库存、活动规则有效。券会过期、门店会调整。
- 不构成任何价格承诺。最终价格以麦当劳官方点餐页为准。
- 本项目为非官方作品，由参赛者独立开发，与麦当劳中国无隶属关系。
